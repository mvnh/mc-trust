# mc-trust

Доверять сертификатам НУЦ Минцифры только для выбранных доменов.

Обычная установка корня Минцифры позволяет ему подтвердить любой сайт, включая `google.com` и `telegram.org`. mc-trust ставит вместо него **grant**: собственный CA и копию корня Минцифры с тем же именем и ключом, но с ограничением имён (`nameConstraints`). Сайты в `.ru`, `.su`, `.рф` и в ваших исключениях открываются, а подменённый сертификат для любого другого домена или IP-адреса система отвергает.

## Установка

Нужны Rust и macOS или Linux. На Linux `install` требует root или sudo, а `check` — `openssl`.

```sh
cargo build --release
sudo cp target/release/mc-trust /usr/local/bin/
```

## Использование

```sh
mc-trust install                     # .ru, .su, .рф
mc-trust install -d sberbank.com     # плюс исключение
mc-trust install --dry-run           # показать план
mc-trust status
mc-trust check online.sberbank.ru sberbank.com
mc-trust uninstall
```

Коды выхода: `0` — успех, `1` — ошибка или ограничение не работает, `3` — проверка неполная (нет сети, сайт не отдал цепочку Минцифры или отказ нечем подтвердить).

## Что делает install

1. Проверяет встроенный корень Минцифры по отпечатку его открытого ключа (SPKI SHA-256 `02b8220c070728db771d9ac59e54521c4eddad21a783bb26cfdf19c1db0fae37`).
2. В памяти выпускает grant: CA (ECDSA P-256) и копию корня. Ключ CA нигде не сохраняется и пропадает сразу после подписи.
3. Ставит grant в системное хранилище.
   - macOS: CA попадает в связку login как доверенный только для SSL, а копия — как промежуточный сертификат без доверия. macOS запросит пароль.
   - Linux: CA и копия записываются файлами в каталог якорей дистрибутива, затем хранилище обновляется. Debian, Ubuntu, Alpine и openSUSE: `/usr/local/share/ca-certificates` (или `/etc/pki/trust/anchors`) и `update-ca-certificates`. Fedora, RHEL и Arch: `/etc/pki/ca-trust/source/anchors` (или `/etc/ca-certificates/trust-source/anchors`) и `update-ca-trust`.
4. Удаляет предыдущий grant, оригинальный корень Минцифры и его промежуточные сертификаты: с ними ограничения обходятся. На macOS это связки login и System (для System нужен `sudo`), на Linux — файлы из каталога якорей.
5. Проверяет результат: `online.sberbank.ru` должен приниматься, `sberbank.com` — отклоняться. Если система принимает `sberbank.com`, grant откатывается.

Повторный `install` выпускает новый grant и убирает старый. Чтобы изменить список доменов, запустите `install` с новыми флагами.

## Ограничения

- Для доменов из списка Минцифры по-прежнему может подменять сертификаты. Защищается всё остальное.
- Зона верхнего уровня в `-d` (например, `-d com`) сводит защиту на нет для всей зоны, поэтому `install` просит подтверждение.
- Firefox, а на Linux также Chrome и Chromium, хранят сертификаты отдельно от системы. mc-trust их не меняет.
- macOS: корень, установленный профилем конфигурации, удаляется только вместе с профилем.
- Linux: если оригинальный корень лежит не в каталоге якорей (в самом бандле или в файле вместе с другими сертификатами), `install` останавливается до изменений и называет, что убрать вручную.
- Linux: в хранилище нет места для недоверенного промежуточного сертификата, поэтому копия корня лежит рядом с CA как обычный якорь. OpenSSL и GnuTLS применяют к ней ограничения (проверено на `curl` и `wget`). Другие библиотеки не проверялись: клиент, который игнорирует ограничения у доверенных сертификатов, увидит в копии обычный корень Минцифры.

## Устройство

- `crates/core` — разбор и сборка X.509, пиннинг корня, выпуск grant'а. Не зависит от ОС, единственная внешняя зависимость — `ring`.
- `crates/cli` — командная строка и два хранилища за общим интерфейсом: связки ключей macOS (`security`) и системное хранилище Linux.

Корень Минцифры взят с <https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt> (сайт Госуслуг) и вшит в бинарник, за сетью mc-trust за ним не ходит. Отпечаток — это SHA-256 от SubjectPublicKeyInfo сертификата, то есть от его открытого ключа. Он защищает от подмены вшитого сертификата или файла, переданного через `--root`. Менять его нужно, только если Минцифры выпустит корень с другим ключом.

`check` получает цепочку через системный `openssl s_client`, а решение о доверии принимает система: на macOS `security verify-cert`, на Linux `openssl verify` по системному хранилищу.

## Разработка

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Тест `crates/core/tests/constraints.rs` проверяет ограничения независимым верификатором OpenSSL: настоящий Sub CA Минцифры проходит через копию, на тестовой цепочке `google.com` и сертификат только с IP-адресом отклоняются с ошибкой «permitted subtree violation». Отдельный тест воспроизводит раскладку Linux, где CA и копия лежат в хранилище вместе.
